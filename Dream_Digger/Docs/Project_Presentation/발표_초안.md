## 세부 초안 작성

1. 프로젝트 개요
	- 프로젝트 스펙 : 프로젝트 기획 문서 참고
	- 이번 프로젝트 목표
		- AI를 활용하지 않고 게임을 완성하는 것. 따라서 핵심 요소를 기준으로 최소 단위를 잡고 기능을 구현하게 되었다.
		- 최소 단위는 타일 파괴 > 자원 획득 > 맵 자동 생성 > 클리어 판정 구현 > 몬스터 구현으로 나누었고, 여기서 클리어 판정 구현까지만 가능했다.
	- 프로젝트를 진행하며 사용한 툴 : GitHub Only. 개인 프로젝트여서 협업툴까지 다루기에는 너무 과하다고 생각하여 깃허브 이슈와 PR을 최대한 활용하여 좋은 기록을 남기는 연습을 목표로 하였다.
2. 기획 소개
	- 레퍼런스 : 굴착소년 쿵
		- 선정한 이유는 게임의 배경이 되는 맵이 곧 상호작용하는 주 대상인 '디거'류에 대해 흥미를 느꼈다. 또한 그 동안 프로젝트를 진행하며 맵에 대해서 다뤄본적이 없었기 때문에 좋은 도전 영역이라고 판단함.
		- 플래시게임임에도 아이템, 체력과 별도로 동작하는 산소시스템, Stage에 따라 달라지는 블록의 효과(미끄러짐 등등) 공부할 요소가 정말 많은 게임이라고 판단했다.
	- 기존 레퍼런스에서 차이를 둔 것
		- 땅을 파는 '디거' 장르이기 때문에 위로도 땅을 팔 수 있도록, 비행중에도 땅을 팔 수 있게 하고 싶었다.
3. 시연영상
4. 핵심 기능 소개
	1. 타일맵을 어떻게 그릴 것인가
		1. 맵이 넓은 만큼 10000개가 넘어가는 게임 오브젝트를 배치하는 것이 고민이였으나, 타일맵의 셀은 게임 오브젝트가 아니기 때문에 게임 오브젝트가 단 하나라는 것을 알게됨.
	2. 타일맵 셀 제거 방식을 선택하고 어려웠던 점
		1. 플레이어는 월드 좌표로 다루는데 셀 좌표는 월드좌표가 아니였다. 따라서 플레이어의 월드 좌표를 상호작용할 때 목표 방향에 있는 셀 좌표로 바꾸는 방식을 선택함. 이 상호작용은 타일맵에 붙어있는 MapController와만 상호작용한다.
	3. 내구도는 어떻게 부여했는가
		1. 좌표(키), 내구도(값)를 가지는 Dictionary를 배치함. 플레이어가 상호작용하면 그려진 타일 종류에 따라 내구도를 담아놓았다가, 타일이 꺼지면 Dictionary에서 제거한다.
	4. 맵 자동 생성 MapGenerator
		1. 타일 맵을 내구도 차감방식으로 제거하는 기능을 완성하고 나니, 맵을 매번 그려내기가 난감했다. 따라서 맵 자동 생성 기능을 만들고자했다. 그려도 좋았지만, 인스펙터에서 직접 설정하는 것이 마우스로 그리는 것보다 정확도가 높을 것이라고 판단함.
		2. 따라서 인스펙터에서 가로 길이, 구역별 세로길이, 구역마다 어떤 타일을 그려낼것인지 설정하게끔 하였다.
	5. 자원 자동 배치 기능
		1. 이제는 맵을 자동생성하는 것이 가능하니 타일에 랜덤으로 자원을 뿌리고, 타일 파괴 시 그려져있는 자원을 뱉어내게하는 기능이 필요해졌다.
		2. 따라서 MemorySpawner 객체를 두었다.
		3. MapGenerator가 구역 번호<키>, 좌표 배열<값>으로 가지는 Dictionary를 채워준다. MemorySpawner는 구역마다 좌표 배열을 Fisher Yates Shuffle로 섞고, 무작위로 섞였기 때문에 인덱스 0번부터 자원을 배치할 수 있게 되었다.
		4. 이제 무작위로 자표를 섞고 배치할 수 있게 되었기 때문에, 구역마다 자원을 얼마만큼 배치할지, 어떤 자원을 얼마만큼 배치할지 정할 수 있어야했다.
		5. 따라서 MapGenarator에서 맵을 생성할 때 밀도, 자원 종류와 가중치 리스트를 설정하고 MemorySpawner는 이 정보를 토대로 등급이 낮은 자원부터 앞에서 배치하게 했다. Special광물은 반복문에서 검사되면 무조건 1개만 배치되고, 가중치가 0이기 때문에 다른 광물 가중치에 영향을 주지 않는다.
		6. 이렇게 하여 맵 자동 생성 기능과 자원 랜덤 자동 배치가 완성 되었다.

		3. 구현 시도 조차 하지 못 한 기능들, 몬스터나 기능이 붙은 기믹 타일 등.
	2. 개선 방향
		1. 세부 구현 방안은 이번에 무엇을 구현하려다 어디서 막혀 어떻게 뚤었는지 작업일지에 많이 남겨놓앗기 때문에 기술문서를 작성하면서 다음 번에 도전해보고 싶다.
		2. 처음 다뤄보는 기능은 빠르게 테스트 씬에서 시도해보는 것이 제일 좋다고 느꼈다. 궁금한 것, 모르는 것은 일단 시도해보고 그 결과를 잘 남기는 것이 나에게 제일 필요하다고 느꼈다.
		3. 구현 못 한 기능은 이번 프로젝트가 끝나고 시간을 내서 조금씩 구현해나가고싶다. 일단 제일 먼저 구현하고 싶은 기능은 몬스터와 몬스터를 무찌를 수 있는 폭탄 아이템, 그리고 몬스터 방을 생성하는 기능이다.
